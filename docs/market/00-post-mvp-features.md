# Доп. требования — вне MVP (пост-курсовой срез)

**Статус:** идеи, зафиксированные для будущего — **ничего из этого не входит в Волны 1–4 основного документа** [`../requirements/01-functional-requirements.md`](../requirements/01-functional-requirements.md) и не учитывается в курсовом срезе (`../requirements/00-overview.md`, §1).

**Зачем отдельная папка:** чтобы не размывать обязательный для защиты курсовой объём (3 модуля РПЗ, ~30 часов) идеями, которые появились из анализа рынка (`../market/00-competitive-analysis.md`), но не были запрошены как часть текущей реализации. Формат ID здесь — `EXTRA-<группа>-NN`, намеренно отдельный от `FR-*`, чтобы не путать с волнами основного документа. Если какой-то пункт отсюда решено взять в реализацию — его нужно переместить (не скопировать) в `01-functional-requirements.md` с присвоением настоящего `FR-*` ID и волны, и удалить отсюда.

## Группа A — дифференциация от рыночных аналогов

Обоснование см. `../market/00-competitive-analysis.md`, §5.

| ID | Требование | Обоснование / зависимость |
|---|---|---|
| EXTRA-DIFF-01 | Пользователь может импортировать существующую структуру во внешнем формате как черновик DSL: SQL DDL → ERD, OpenAPI/JSON-схема → sequence/class-диаграмма, структура папок git-репозитория → C4-диаграмма. | Ни один прямой конкурент (включая Eraser.io) не делает структурный парсинг схем, а не просто «генерация из репозитория» текстом — реальная точка отличия, не косметика. Технически — новый модуль в `integrations/importers/`, использующий существующий `DiagramModel` как общую цель разбора, без изменения `dsl/`-ядра. |
| EXTRA-DIFF-02 | Система предоставляет MCP-сервер, позволяющий внешним AI-агентам (Claude Code, Cursor и т.п.) создавать/читать/обновлять диаграммы через тот же API, что и обычные пользователи. | Прямая параллель с Eraser.io (MCP уже есть у них). Естественное расширение уже существующего REST API — не отдельная подсистема, а ещё один клиент поверх `services/diagram_service.py`. |
| EXTRA-DIFF-03 | Система умеет генерировать текстовое alt-описание диаграммы для скринридеров через AI (обратная генерация: диаграмма → связный текст). | Ни у одного из проанализированных конкурентов нет как продуктовой фичи, не только как побочный эффект — усиливает NFR-A11Y-раздел, а не декорация. |

## Группа B — AI глубже генерации кода

| ID | Требование | Обоснование / зависимость |
|---|---|---|
| EXTRA-AI-01 | DSL-линтер: стилевые предупреждения независимо от структурной валидации нотации — избыточное число узлов на одной диаграмме, изолированные узлы без единой связи, несоответствие соглашению об именовании идентификаторов. | Отдельный уровень поверх `NotationProfile.validate` — линтер общий для всех нотаций, в отличие от структурной валидации, которая нотация-специфична. |
| EXTRA-AI-02 | AI может составить связное текстовое описание уже существующей диаграммы («что делает этот процесс») — обратный сценарий к FR-AI-03 (текст → DSL). | Использует тот же `AIProvider`-интерфейс, новый метод протокола (`describe_diagram`), не требует изменения архитектуры домена. |
| EXTRA-AI-03 | Презентационный режим пошагового просмотра декомпозиции IDEF0/DFD («drill-down tour» по уровням parent→children). | Использует уже существующую модель `parent_diagram_id`/`decomposed_node_id` (FR-NOT-06a) — чисто фронтенд-фича поверх готовых данных, бэкенд не меняется. |

## Группа C — совместная работа и шеринг

| ID | Требование | Обоснование / зависимость |
|---|---|---|
| EXTRA-COLLAB-01 | Публичная read-only ссылка на диаграмму без необходимости логина/аккаунта у смотрящего. | Стандартная фича у Mermaid Live/Eraser/Lucidchart; критично для показа диаграммы человеку без учётной записи (например, комиссии на защите). Требует отдельного, ограниченного по правам публичного эндпоинта — не переиспользовать основной `GET /diagrams/{id}` напрямую (иначе теряется 404-вместо-403 гарантия FR-AUTH-06 для приватных диаграмм). |
| EXTRA-COLLAB-02 | Комментарии на конкретных узлах диаграммы (аналог комментариев Figma). | Дешевле в реализации, чем полноценное совместное редактирование (FR-AUTH-08, Волна 2) и даёт ценность раньше — отдельная модель `NodeComment`, не требует WebSocket-синхронизации текста. |
| EXTRA-COLLAB-03 | Presence-индикаторы — кто сейчас просматривает/редактирует диаграмму. | Естественное расширение уже архитектурно заложенного WebSocket pub/sub (см. `../architecture/00-system-architecture.md`, §3, п.3) — не новая инфраструктура, новый тип сообщения в существующем канале. |

## Группа D — Developer Experience и интеграции

| ID | Требование | Обоснование / зависимость |
|---|---|---|
| EXTRA-DEV-01 | CLI-утилита (`diagramcode render file.dsl`) для рендера DSL-файлов в CI/CD (docs-as-code, автообновление SVG при пуше в репозиторий). | Переиспользует существующий `dsl/parser.py` + `NotationProfile.render` как библиотеку — тонкая обёртка, не новая логика. |
| EXTRA-DEV-02 | Расширение для VS Code с подсветкой синтаксиса DSL и live-превью рендера прямо в редакторе, без открытия веб-приложения. | Одна из причин популярности PlantUML/Mermaid — снижает порог входа для разработчиков, которые не хотят покидать IDE. |
| EXTRA-DEV-03 | Webhook/API для внешних интеграций (например, Slack-бот «покажи диаграмму», обновление по событию из внешней системы). | Требует отдельного слоя подписок на события — не блокирует остальную архитектуру, реализуется как ещё один consumer очереди событий. |

## Группа E — качество и автономность

| ID | Требование | Обоснование / зависимость |
|---|---|---|
| EXTRA-QUAL-01 | Индекс сложности диаграммы (аналог цикломатической сложности) с рекомендацией «разбить через декомпозицию», когда диаграмма становится слишком большой. | Использует ту же модель декомпозиции, что EXTRA-AI-03 — чисто аналитическая метрика поверх `DiagramModel`, не меняет хранение. |
| EXTRA-QUAL-02 | Offline/desktop-обёртка (например, Tauri) поверх уже запланированного PWA (NFR-PWA-01…03) — полноценная работа без сети, не только кэш последнего состояния. | Расширяет уже принятое PWA-решение, не конкурирует с ним — тот же frontend-код, дополнительная упаковка. |

## Как обращаться с этим документом дальше

- Не реализовывать ничего отсюда без явного запроса — это чистый бэклог идей, не подтверждённые к разработке требования.
- При переносе пункта в `01-functional-requirements.md` — присвоить реальный `FR-*` ID и волну (скорее всего Волна 4+ или отдельная «Волна 5: пост-MVP», если пунктов наберётся достаточно много для отдельной волны), и удалить пункт из этого файла, чтобы не было двух источников истины по одному требованию.
