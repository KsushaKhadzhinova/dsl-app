# Пользовательские требования (User Requirements)

**Статус:** актуально
**Отличие от функциональных требований:** пользовательские требования написаны языком пользователя («я хочу мочь...»), без указания, как именно система это реализует. Технический контракт — в `01-functional-requirements.md`; сценарии — в `03-use-cases.md`.

| ID | Пользователь хочет... |
|---|---|
| UR-01 | ...зарегистрироваться и войти в систему по email и паролю, не создавая лишних учётных записей |
| UR-02 | ...писать диаграмму текстом и сразу видеть, как она выглядит, без переключения между инструментами |
| UR-03 | ...понимать, где именно в коде ошибка, если диаграмма не отрендерилась |
| UR-04 | ...не терять предыдущие версии диаграммы, если что-то испортил в текущей правке |
| UR-05 | ...получить черновик диаграммы по текстовому описанию или загруженному изображению, если не хочет писать DSL с нуля |
| UR-06 | ...работать с несколькими типами диаграмм (ER, BPMN, UML, IDEF0) в одном инструменте, не изучая разные программы под каждую |
| UR-07 | ...скачать результат в удобном формате (файл на устройство, картинка, текст для другого инструмента) |
| UR-08 | ...пригласить коллегу редактировать диаграмму вместе, не пересылая файлы вручную |
| UR-09 | ...работать в интерфейсе на удобном языке (русский или английский) и в комфортной цветовой теме |
| UR-10 | ...быть уверенным, что его пароль и данные не видны никому, включая разработчиков системы |
