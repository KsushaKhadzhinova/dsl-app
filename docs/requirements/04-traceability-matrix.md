# Матрица трассируемости и статус реализации

**Статус:** актуально на 2026-09-17 (снимок по факту наличия файлов в `backend/app/`, `backend/tests/`, `frontend/`; будет уточнено после интеграции результатов фонового агента по реальному IDE-фронтенду)
**Связанные документы:** [`01-functional-requirements.md`](01-functional-requirements.md), [`../architecture/00-system-architecture.md`](../architecture/00-system-architecture.md)

Назначение документа — не дублировать колонку «Источник» из FR-таблиц, а зафиксировать **реальный статус реализации** каждой группы требований на текущий момент: что уже есть в коде и покрыто тестами, что в работе, что только запланировано волной. Это ровно то, чем в реальном проекте занимается аналитик перед статус-встречей — сверяет требования с фактическим состоянием репозитория, а не с намерениями.

Условные обозначения: ✅ реализовано и покрыто тестами · 🔶 в работе (создан код/агент работает, тесты не полные или UI не подключён) · ⬜ запланировано (волна ещё не наступила) · ⚠️ обнаружен пробел (тег волны говорит "уже должно быть", а по факту нет)
