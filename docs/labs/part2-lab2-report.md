## 2 ХОД РАБОТЫ

### 2.1 Обзор предметной области

Предметная область осталась прежней — сервис *DiagramCode*, основная сущность «Диаграмма»
(*Diagram*). По сравнению с лабораторной работой №1 в модель добавлено новое поле *status*

массиве на постоянное хранение в реляционной базе данных *PostgreSQL*.

### 2.2 Теоретические сведения

*ORM* (*Object*-*Relational Mapping*) — прослойка, которая превращает строки таблиц *SQL*-базы
в обычные объекты *JavaScript* и обратно. Вместо ручного *SQL*-запроса *SELECT* * *FROM*
"*Diagrams*" *WHERE id* = 5 пишется *Diagram*.*findByPk*(5) — *Sequelize* сам генерирует *SQL*,
выполняет его через драйвер *pg* и оборачивает результат в объект с методами (.*update*(),
.*destroy*() и т.п.).

Преимущества такого подхода — отсутствие необходимости писать сырой *SQL* вручную,
параметризованные запросы, защищающие от *SQL*-инъекций «из коробки», валидация данных на
уровне модели ещё до похода в базу и миграции как контролируемая, воспроизводимая история
изменений схемы. Из недостатков — сложные джойны и агрегации *ORM* генерирует не всегда
оптимально, и сам по себе это дополнительный слой абстракции, который нужно изучать отдельно
от *SQL*.

### 2.5 Реализация *CRUD* и тестирование через *Postman*

Контроллер реализует пять операций: *getAll* (*Diagram*.*findAll*()), *getById*
(*Diagram*.*findByPk*(*id*), 404 при отсутствии записи), *create* (*Diagram*.*create*(*req*.*body*),

204 при успехе, 404 если *deletedCount* равен нулю). Все пять маршрутов протестированы через
*Postman* против реальной базы *Neon*, включая намеренную проверку ошибки валидации (пустой

## 3 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

**1. Что такое *ORM*? Какие преимущества и недостатки его использования?**
*ORM* — прослойка между объектами *JavaScript* и таблицами *SQL*-базы, см. раздел 2.2.
Преимущества: отсутствие сырого *SQL*, защита от инъекций, валидация на уровне модели,
управляемые миграции. Недостатки: не всегда оптимальные сложные запросы, дополнительный слой
абстракции для изучения.

**2. Как *Sequelize* преобразует названия моделей в имена таблиц?**
По умолчанию имя модели переводится в *PascalCase* и множественное число (*Diagram* →
*Diagrams*). В проекте это явно закреплено опцией *tableName*: "*Diagrams*", чтобы не зависеть
от версии библиотеки плюрализации.

**3. Как выполнить поиск с условием (*WHERE*) в *Sequelize*? Приведите пример.**
*Diagram*.*findAll*({ *where*: { *notation*: "*bpmn*" } }) — вернёт только диаграммы этой
нотации. Тот же принцип используется в проекте в *destroy*({ *where*: { *id* } }).

**4. Что такое миграции и зачем они нужны?**
Миграция — файл с функциями *up* (применить изменение схемы) и *down* (откатить). Миграции
коммитятся в *git* и применяются командой, что даёт воспроизводимую, контролируемую историю
изменений структуры базы данных вместо ручных правок через *SQL*-консоль.

**5. Как реализовать связь один-ко-многим между моделями? Приведите пример из вашего проекта.**
В текущей лабораторной работе связь не реализована (одна таблица *Diagrams*), но по аналогии:
*Diagram*.*hasMany*(*Comment*) на стороне «одного» и *Comment*.*belongsTo*(*Diagram*, {
*foreignKey*: "*diagramId*" }) на стороне «многих» — *Sequelize* сам добавит колонку
*diagramId* в таблицу *Comments*.

**6. Как выполнить пагинацию (*limit*, *offset*) в *Sequelize*?**
*Diagram*.*findAll*({ *limit*: 10, *offset*: 20 }) — вернёт строки с 21-й по 30-ю.

**7. Как обработать ошибку уникальности (*duplicate entry*) при создании записи?**
*Sequelize* выбрасывает *SequelizeUniqueConstraintError* — подкласс *ValidationError*, поэтому
ловится тем же условием *err instanceof ValidationError*, что и обычные ошибки валидации полей.

**8. Чем отличается *findByPk* от *findOne*?**
*findByPk* ищет только по значению первичного ключа — быстрее, есть гарантированный индекс.
*findOne* принимает произвольное условие *where* и может искать по любому полю или их
комбинации.

**9. Как добавить кастомный метод в модель *Sequelize*?**
Статический метод — через *Diagram*.*someMethod* = *function*() {...}; метод экземпляра — через
третий аргумент *sequelize*.*define* либо прямое расширение *Diagram*.*prototype*.

**10. Какие типы связей поддерживает *Sequelize* (*belongsTo*, *hasMany*, *belongsToMany*)?**
*belongsTo* — много-к-одному со стороны «многих»; *hasMany* — один-ко-многим со стороны
«одного»; *belongsToMany* — многие-ко-многим через промежуточную таблицу.

## ПРИЛОЖЕНИЕ А (обязательное). Листинг контроллера *diagramController*.*js*

```js
const { ValidationError } = require("sequelize");
const Diagram = require("../models/Diagram");

async function getAll(req, res, next) {
  try {
    const diagrams = await Diagram.findAll();
    res.status(200).json(diagrams);
  } catch (err) {
    next(err);
  }
}

async function getById(req, res, next) {
  try {
    const diagram = await Diagram.findByPk(req.params.id);
    if (!diagram) {
      return res.status(404).json({ error: "Диаграмма не найдена" });
    }
    res.status(200).json(diagram);
  } catch (err) {
    next(err);
  }
}

async function create(req, res, next) {
  try {
    const diagram = await Diagram.create(req.body);
    res.status(201).json(diagram);
  } catch (err) {
    if (err instanceof ValidationError) {
      return res.status(400).json({ error: err.errors.map((e) => e.message).join(", ") });
    }
    next(err);
  }
}

module.exports = { getAll, getById, create };
```
