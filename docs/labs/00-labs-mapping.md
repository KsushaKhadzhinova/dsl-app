# Привязка лабораторных работ ИТиВП к проекту DiagramCode

**Статус:** актуально
**Источник списка лабораторных:** официальные материалы дисциплины «Интернет-технологии и веб-программирование» (БГУИР), `E:\ИТиВП\Часть 1\` и `E:\ИТиВП\Часть 2\` (методички по модулям, вне этого репозитория).

Дисциплина состоит из двух частей, в каждой — 8 лабораторных работ. Курсовое проектирование (см. `docs/architecture/00-system-architecture.md`) относится к Части 2. Ниже — для каждой лабораторной работы указано, какой частью DiagramCode она закрывается, и учтено осознанное отклонение технологического стека (Python/FastAPI вместо Node.js/Express, PostgreSQL вместо MongoDB) — обоснование в `docs/architecture/00-system-architecture.md`, §2.

**Важно:** лабораторные, привязанные к технологиям, от которых DiagramCode сознательно отказался (чистый Node.js-сервер, Sequelize, MongoDB), выполняются в отдельных учебных ветках репозитория (`lab21`, `lab12`, `pz21`) как самостоятельные учебные артефакты — они **не являются частью продукта DiagramCode** и не описываются в `docs/requirements/`. Эта таблица лишь фиксирует, где именно засчитывается каждая лабораторная, чтобы не терять из вида общий зачёт по дисциплине.

## Курсовое проектирование (отдельно от лабораторных 1–8)

Курсовая работа «Разработка веб-приложения» (Часть 2) — не лабораторная работа, а отдельный зачётный документ (пояснительная записка, 20–30 стр., см. `Часть 2/Курсовое проектирование/03. Структура пояснительной записки к курсовой работе.pdf`). Её объём — DiagramCode целиком, но **писать РПЗ достаточно по Волне 1** (курсовой срез, см. `docs/requirements/00-overview.md`, §1): DSL-редактор + рендер + сохранение + нотация `erd.crows_foot.logical` с валидацией + аутентификация. Структура РПЗ (главы 1–3, введение, заключение, список источников, приложения) и обоснование отклонений от шаблона (FastAPI вместо Express, модульный монолит вместо микросервисов) уже подготовлены в `docs/architecture/00-system-architecture.md` — этот документ можно использовать как основу для главы 1.2 РПЗ («Проектирование архитектуры приложения»), а `docs/literature/bibliography.md` — как основу раздела «Список использованных источников».
