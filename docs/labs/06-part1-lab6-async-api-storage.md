# ИТиВП, Часть 1 — Лабораторная работа 6: Асинхронность, внешний API, LocalStorage

Ветка: `feature/async-api-storage` (от `main`, влита обратно в `main`).

## Компонент

Виджет "Проект вживую" (`#repo-stats`) на главной странице: подтягивает реальные метрики
собственного репозитория `KsushaKhadzhinova/dsl-app` через публичный GitHub REST API
(без токена, эндпоинт `GET /repos/{owner}/{repo}`) — звёзды, форки, открытые issues, дата
последнего коммита. Файл: `frontend/js/repoStats.js`.

## Fetch API

`fetch(REPO_API_URL)` → проверка `response.ok` (GitHub может вернуть 404/403 при лимите
запросов) → `response.json()`. Полностью асинхронно, через `async/await`.

## LocalStorage-кэширование

Ключ `dc-repo-stats`, хранится `{ data, cachedAt }`. TTL — 10 минут (`CACHE_TTL_MS`):
- Если кэш свежий — рендерим из него, сеть вообще не трогаем (экономит квоту публичного API,
  у которой лимит 60 запросов/час без авторизации).
- Если кэш устарел или отсутствует — идём в сеть.
- Если сеть недоступна или API вернул ошибку — при наличии **хоть какого-то** (пусть и
  устаревшего) кэша показываем его вместо ошибки; если кэша вообще нет — показываем текст ошибки.
- Битый JSON в LocalStorage (`JSON.parse` бросает исключение) обрабатывается как отсутствие кэша.

## Обработка ошибок

Три независимых сценария покрыты и в коде, и в тестах: не-200 ответ API, сетевой сбой
(`fetch` реджектится), повреждённые данные в LocalStorage.

## Исправление после сверки с полным текстом задания

Задание прямо просит структуру `js/api/{apiService.js,config.js}` + `js/storage/localStorage.js`
+ `js/utils/dataParser.js` — изначально всё лежало в одном `js/repoStats.js`. Исправлено на
ветке (отдельный коммит): `api/config.js` (URL GitHub API), `api/apiService.js` (сам `fetch`,
принимает `AbortSignal`), `utils/dataParser.js` (преобразование сырого ответа GitHub в форму
для UI), `storage/localStorage.js` (кэш с TTL поверх общего `utils/storage.js` из Lab 5),
`components/repoStats.js` (оркестрация + DOM).

Также реализованы 2 пункта из «Часть 6. Дополнительные требования» (задание просит минимум
два, изначально не было ни одного):
- **Кнопка «Обновить»** — принудительный повторный запрос к API в обход свежего кэша.
- **`AbortController`** — повторный клик по «Обновить» отменяет ещё не завершившийся
  предыдущий запрос вместо того, чтобы оставлять его гонку с новым.

## Тесты

`frontend/tests/repoStats.test.js`, 8 тестов, `global.fetch` замокан через `jest.fn()`:
секция отсутствует на странице → сеть не трогаем; успешный ответ → рендер + запись кэша;
свежий кэш → рендер без сети; протухший кэш → повторный запрос; ошибка без кэша → текст
ошибки; сетевой сбой без кэша → текст ошибки; сбой при наличии устаревшего кэша → рендер
кэша вместо ошибки; битый JSON в кэше → трактуется как отсутствие кэша.

Прогон: **100% statements / branches / functions / lines** по `repoStats.js`
(порог в `package.json` защищает от регресса).
