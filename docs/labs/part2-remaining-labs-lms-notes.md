## Lab3 — Аутентификация и авторизация

Источник: страницы "Регистрация и аутентификация пользователей", "JWT (JSON Web Token)" модуля 1.

- Хеширование: **bcrypt**, `saltRounds = 12`, `bcrypt.hash`/`bcrypt.compare`.
- Токены: **JWT** (`jsonwebtoken`), `jwt.sign({ userId }, JWT_SECRET, { expiresIn: '7d' })`, передача через заголовок `Authorization: Bearer <token>`.
- Middleware проверки токена: читает заголовок, `jwt.verify`, кладёт `req.userId`, иначе 401.
- Регистрация: обязательные поля email (уникальный, lowercase) + пароль + подтверждение; валидация пароля (мин. 8 символов, верхний/нижний регистр, цифры, спецсимволы), список запрещённых распространённых паролей.
- Вход: поиск по email → сравнение хэша → **generic-сообщение об ошибке** (не раскрывать, email не найден или пароль неверный — "Неверные учетные данные") → счётчик `loginAttempts`, блокировка после 5 неудачных попыток → сброс счётчика при успехе → проверка `isActive`.
- Ветка: `lab23` (от `lab12`).

## Lab6 — MongoDB (Mongoose)

Источник: "ODM Mongoose: схемы, модели" модуля 3.

- **MongoDB Atlas** (бесплатный кластер, аналогично Neon для Postgres) + **Mongoose** ODM.
- Схема/модель: `new Schema({...}, {timestamps:true})`, `mongoose.model('Name', schema)`.
- CRUD-методы точно по документации: `save()`/`create()`, `find()`/`findById()`/`findOne()`, `updateOne()`/`findByIdAndUpdate(id, data, {new:true})`, `deleteOne()`/`findByIdAndDelete()`.
- Валидация на уровне схемы (`required`, `minlength`/`maxlength`, `match` regex, `min`/`max` для чисел) — не только в контроллере.
- Реальная сущность для этой лабы — новая коллекция в духе предметки DiagramCode (например, комментарии к диаграмме, или лог AI-запросов — что-то, для чего документная модель уместнее реляционной).
- Ветка: `lab26` (от `pz24`, т.к. это последняя точка ветки Часть 2 на этот момент — либо от `lab25`, если практики считать отдельной параллельной цепочкой — уточнить порядок при реализации, не критично).

## Lab7 — WebSocket

Источник: "Веб-сокеты и реальное время" модуля 3.
