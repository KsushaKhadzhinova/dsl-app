## Требования без тест-кейсов (сознательно, не по забывчивости)

- Все FR, помеченные ⬜ «запланировано» в `../requirements/04-traceability-matrix.md` — нет смысла писать тест-кейс на нереализованный код; сначала реализация, потом тест (Entry criteria из `00-test-plan.md`, п.7).
- NFR из раздела 1 `01-requirements-testability-review.md` — сначала нужно уточнение формулировки, потом тест-кейс.

## Тест-кейсы без явной привязки к FR (обнаруженные в процессе, не помеченные заранее)

Ни одного на момент написания — все тест-кейсы в `02-test-cases.md`/`03-api-test-cases.md` созданы по конкретному FR/NFR ID. Если в будущем появится тест «просто потому что так интуитивно ожидается» без привязки к ID — это сигнал, что либо требование не задокументировано и его нужно добавить в `01-functional-requirements.md`, либо тест лишний.
