# Шаблон баг-репорта и шкалы Severity/Priority

**Статус:** актуально

## Шкала Severity (влияние — определяет тестировщик)

| Severity | Значение для DiagramCode |
|---|---|
| **Blocker** | Функциональность полностью недоступна, тестирование дальше невозможно — напр. `/login` вообще не отправляет запрос ни при каких данных. |
| **Critical** | Сломана ключевая бизнес-логика без обходного пути — напр. рендер ERD всегда возвращает пустой SVG; ИЛИ важная функция сломана, но обходной путь есть (напр. Save не работает, но экспорт «на устройство» позволяет не потерять код). |
| **Major** | Важная часть одного сценария сломана при конкретных условиях, или есть обходной путь — напр. BPMN-валидация не ловит связь на несуществующий узел, но остальная валидация BPMN работает. |
| **Minor** | Не ломает функциональность, но мешает использованию — напр. счётчик ошибок в статус-баре не кликабелен. |
| **Trivial** | Косметика — опечатка в тексте тоста, несовпадение цвета акцента на 1 оттенок. |

## Шкала Priority (срочность — определяет владелец проекта/лид)

| Priority | Значение |
|---|---|
| **ASAP** | Блокирует текущую сдачу лабы/защиту — чинить немедленно. |
| **High** | Важно для ближайшей волны/защиты, но не блокирует текущий шаг. |
| **Medium** | Нужно починить, но не срочно. |
| **Low** | Когда будет время. |

Severity и Priority — независимые оси: опечатка (Trivial) на экране логина, который завтра показывают комиссии, может быть High priority. Дефект в ещё не зарегистрированной нотации (IDEF0) может быть Critical severity, но Low priority, пока эта нотация не заявлена в текущей волне.

## Шаблон баг-репорта

```
ID: (авто)
Заголовок: [Компонент] Краткое и конкретное описание — что и при каких условиях

Окружение: локально (Docker Compose) / CI
Версия/коммит: <git-хэш или номер ветки>
Браузер (если применимо): 

Шаги воспроизведения:
1. ...
2. ...
3. ...

Фактический результат:
<что произошло>

Ожидаемый результат:
<что должно было произойти, со ссылкой на конкретный FR/NFR ID, если применимо>

Severity: Blocker / Critical / Major / Minor / Trivial
Priority: ASAP / High / Medium / Low (заполняется владельцем, не тестировщиком)

Вложения: скриншот / видео / лог / HTTP-запрос-ответ (для API-багов)
```

## Жизненный цикл дефекта в этом проекте (упрощённо для соло-разработки)

New → (Fix in progress) → Fixed → Retested → Closed, либо New → Declined (если это не баг, а недокументированное, но осознанно принятое поведение — см. `01-requirements-testability-review.md` о том, что не всякая неточность формулировки означает баг в коде) / Deferred (реальный баг, но отложен на следующую волну — фиксировать в `../requirements/05-risk-register.md`, если он связан с известным риском).
