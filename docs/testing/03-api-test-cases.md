# API-тест-кейсы

**Статус:** актуально
**Метод:** по чек-листу `api-testing.md` (скилл `qa-tester`) — для каждого эндпоинта проверяются позитив, негатив, границы, а не только код ответа (совпадение статус-кода — не доказательство правильного поведения).

## `POST /api/v1/auth/register`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-AUTH-01 | Валидная регистрация | `{email, username, password}` — все поля корректны | 201/200, тело без поля пароля/хэша |
| API-AUTH-02 | Занятый email | Повтор с тем же email | 400/409, вторая запись User не создаётся (проверить через прямой запрос к БД/через `GET` профиля, а не только по коду ответа) |
| API-AUTH-03 | Отсутствует обязательное поле | Без `password` в теле | 422 (Pydantic-валидация), тело содержит понятное имя поля с ошибкой |
| API-AUTH-04 | Неверный Content-Type | Тело как `text/plain` вместо `application/json` | 415 или 422 — не 500 |
| API-AUTH-05 | Пароль в ответе никогда не раскрывается | Любой успешный запрос | Тело ответа не содержит `password`/`password_hash` ни в каком виде (NFR-SEC-01) |

## `POST /api/v1/auth/login`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-AUTH-06 | Валидный логин | Верные email+пароль | 200, `access_token` в теле, валидный JWT (проверить декодированием — есть `sub`/`exp`) |
| API-AUTH-07 | Неверный пароль | Верный email, неверный пароль | 401 |
| API-AUTH-08 | Повторный логин (не должен плодить сессии/токены аномально) | Логин дважды подряд | Оба запроса успешны, оба токена валидны независимо (если система не использует single-session-token модель — если использует, второй логин должен инвалидировать первый токен, это нужно явно уточнить и задокументировать выбранное поведение) |

## `GET /api/v1/diagrams`, `POST /api/v1/diagrams`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-DIAG-01 | Список диаграмм текущего пользователя | `GET` с валидным токеном | 200, только диаграммы этого `user_id` (или где он совладелец/соавтор) — не диаграммы других пользователей |
| API-DIAG-02 | Список без токена | `GET` без заголовка `Authorization` | 401 |
| API-DIAG-03 | Создание диаграммы | `POST {title, notation}` | 201, тело содержит `id` новой диаграммы |
| API-DIAG-04 | Создание с несуществующей нотацией | `POST {title, notation: "not.a.real.notation"}` | 400/422 — не 500, не тихое создание с мусорным значением в поле `notation` |
| API-DIAG-05 | Создание с пустым `title` | `POST {title: "", notation: "erd.crows_foot.logical"}` | 422 (граница длины title — уточнить min length в схеме, если 0 недопустимо) |

## `GET /api/v1/diagrams/{id}`, `GET /api/v1/diagrams/{id}/export`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-DIAG-06 | Детали своей диаграммы | `GET` владельцем | 200, включает разрешённый `current_commit_id`-контент (см. архитектурный аудит — это поле было «мёртвым», теперь подключено) |
| API-DIAG-07 | Детали чужой диаграммы | `GET` пользователем без доступа | 404 (не 403 — FR-AUTH-06) |
| API-DIAG-08 | Несуществующий id | `GET /diagrams/{random-uuid}` | 404 |
| API-DIAG-09 | Невалидный формат id (не UUID) | `GET /diagrams/not-a-uuid` | 422/400, не 500 |
| API-DIAG-10 | Экспорт с кириллическим названием файла | `GET /diagrams/{id}/export`, где `title` содержит кириллицу | `Content-Disposition` корректно закодирован (RFC 5987) — это конкретный баг, который бэкенд-агент нашёл и исправил; тест должен явно проверить именно этот случай как регрессионный |

## `POST /api/v1/diagrams/render`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-REN-01 | Валидный DSL, валидная нотация | `{dsl_content, notation}` корректны | 200, тело содержит `svg`/`issues: []` |
| API-REN-02 | Синтаксическая ошибка | Невалидный DSL-синтаксис | 400, тело содержит `line`/`column`/`message` |
| API-REN-03 | Ошибка валидации нотации | Синтаксически валиден, но нарушает правила нотации | 200 (или 4xx — уточнить контракт: рендер не выполнен, но это не «ошибка запроса» в HTTP-смысле — сверить с фактическим кодом, не предполагать) с `issues` содержащими severity `error`, без `svg`/с `svg: null` |
| API-REN-04 | Только предупреждение | ERD без PK | 200, `svg` присутствует, `issues` содержит 1 warning |
| API-REN-05 | Пустой `dsl_content` | `{dsl_content: "", notation: "erd.crows_foot.logical"}` | 400/422, не 500 |

## `POST /api/v1/diagrams/{id}/versions`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-VER-01 | Валидное сохранение | `{dsl_content, message}` | 201, `commit.id` в ответе |
| API-VER-02 | Повторное сохранение идентичного контента | Тот же `dsl_content` дважды | Второй `Commit` ссылается на тот же `blob_id` (см. TC-VER-02) |
| API-VER-03 | Сохранение чужой диаграммы | Соавтор без прав записи (viewer-роль, если такая вводится) или посторонний | 403 (для легитимного viewer) или 404 (для постороннего) — не смешивать эти два случая |

## `POST /api/v1/ai/generate`

| ID | Сценарий | Запрос | Ожидаемый ответ |
|---|---|---|---|
| API-AI-01 | Валидный запрос в пределах квоты | `{mode: "write", prompt, notation}`, квота не исчерпана | 200, `dsl_code` в ответе, запись в `ai_requests` создана |
| API-AI-02 | Превышение квоты (21-й запрос) | См. TC-AIQ-03 | 429, `ai_requests` не создаётся, `AIProvider` не вызывается (проверить через отсутствие сетевого вызова/через мок-счётчик) |
| API-AI-03 | Невалидный `mode` | `{mode: "not_a_real_mode", ...}` | 422 |
| API-AI-04 | Без авторизации | Без токена | 401, запрос не доходит до проверки квоты |
| API-AI-05 | `AI_PROVIDER=stub` (без реального ключа) | Любой валидный запрос | 200, детерминированный ответ заглушки, без сетевого обращения (NFR-REL-01) |

## Общее для всех защищённых эндпоинтов

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| API-SEC-01 | Истёкший JWT | 401 на любом защищённом эндпоинте |
| API-SEC-02 | JWT с подделанной подписью | 401, не 500 (даже если структурно похож на валидный) |
| API-SEC-03 | SQL/NoSQL-инъекция в текстовых полях (title, prompt, dsl_content) | Значение обрабатывается как обычная строка (параметризованные запросы через SQLAlchemy) — ни один тест не должен приводить к ошибке БД или обходу авторизации |
