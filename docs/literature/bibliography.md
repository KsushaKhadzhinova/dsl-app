# Библиография проекта DiagramCode

Полный список литературы и источников, использованных при проектировании системы — сгруппирован по темам. Внутри каждой группы — сквозная нумерация для удобной ссылки из кода/документов (`[42]`). Список отмеченных ★ источников — минимальный набор (15–20), которого по объёму достаточно для раздела «Список использованных источников» в РПЗ (см. `docs/architecture/00-system-architecture.md`); остальные — рабочие источники, на которые опираются конкретные архитектурные решения, но не обязательные для списка литературы в РПЗ.

---

## 1. Чистый код и рефакторинг

1. ★ Мартин Р. «Чистый код» (Clean Code). — Именование, функции, границы модулей; основа для структуры `dsl/`, `services/`, `notations/`.
2. Томас Д., Хант Э. «Программист-прагматик» (The Pragmatic Programmer). — DRY, автоматизация рутины, отношение к тестам как к контракту.
3. ★ Фаулер М. «Рефакторинг. Улучшение проекта существующего кода». — Каталог безопасных преобразований кода; применяется при переходе плагинов нотаций от волны к волне (§5 архитектуры).

## 2. Архитектура приложений

4. ★ Мартин Р. «Чистая архитектура» (Clean Architecture). — SOLID, независимость домена от фреймворка; прямой источник слоёв `api/services/repositories/domain` (§4 архитектуры).
5. Фаулер М. «Шаблоны корпоративных приложений» (Patterns of Enterprise Application Architecture). — Repository, Data Mapper, Unit of Work — легли в основу слоя `repositories/`.
6. ★ Ричардс М., Форд Н. «Фундаментальный подход к программной архитектуре» (Fundamentals of Software Architecture). — Оценка архитектурных компромиссов (fitness functions), обоснование выбора «модульный монолит + очередь» вместо микросервисов (§3).
7. ★ Фаулер М. Статья «MonolithFirst» (martinfowler.com). — Прямое обоснование решения не дробить систему на микросервисы без независимой причины масштабирования.

## 3. Распределённые и клиент-серверные системы

8. ★ Клеппман М. «Высоконагруженные приложения» (Designing Data-Intensive Applications). — Репликация, партиционирование, консистентность; обоснование выбора PostgreSQL для git-подобного версионирования (§6).
9. ★ Ньюман С. «Создание микросервисов» (Building Microservices). — Границы сервисов по бизнес-возможностям; предостережение против преждевременного дробления, использовано вместе с MonolithFirst.
10. Бернс Б. «Designing Distributed Systems». — Паттерны Work Queue и Sidecar; Work Queue — прямая основа воркер-пула (§3, п.1–2).
11. Эйсмонт А. «Web Scalability for Startup Engineers». — Балансировка нагрузки, кэширование — обоснование роли Redis как кэша рендер-результатов (§6).

## 4. Диаграммы, документирование, C4

12. ★ Фаулер М. «UML. Основы» (UML Distilled). — Практическая нотация класс/sequence/activity диаграмм без академической перегрузки.
13. Браун С. «Software Architecture for Developers» (модель C4). — Многоуровневые архитектурные диаграммы (Context → Container → Component → Code); использована как «Альтернатива» физической схеме в п. 1.2 РПЗ.
14. ISO/IEC 19505:2012 (UML 2.x) — формальная спецификация метамодели UML, основа профилей `notations/uml/*`.
15. ISO/IEC 19510:2013 (BPMN 2.0) — формальная спецификация BPMN, основа профиля `notations/bpmn`.
16. Camunda, GBTEC, HEFLO — практические руководства по символам и композиции BPMN 2.0 (дополняют формальный стандарт примерами).

## 5. Разработка DSL и парсеров

17. ★ Фаулер М. «Предметно-ориентированные языки программирования» (Domain-Specific Languages). — Классификация внутренних/внешних DSL; собственный язык диаграмм — внешний DSL.
18. Нистром Р. «Crafting Interpreters». — Построение лексера → парсера → AST с нуля; основа модулей `dsl/tokens.py`, `dsl/lexer.py`, `dsl/parser.py`.
19. Ахо А., Лам М., Ульман Д. «Компиляторы: принципы, технологии и инструментарий» (Dragon Book). — Теоретическая база лексического/синтаксического анализа для формального описания грамматики DSL в РПЗ.
20. Документация **Lark** и **textX** (Python) — практический инструмент построения грамматик; выбран вместо ANTLR как более лёгкий для DSL такого размера (см. §2 архитектуры).
21. Форма **EBNF** — формальная нотация для описания грамматики DSL в тексте РПЗ.

## 6. Паттерны на Python и структура бэкенда

22. ★ Персиваль Г., Грегори Б. «Паттерны разработки на Python» (Cosmic Python / Architecture Patterns with Python). — Repository, Unit of Work, Service Layer на практике — прямой прообраз `repositories/` и `services/`.
23. Документация **FastAPI** и **Pydantic** — контракты API, авто-генерация OpenAPI (пересекается с лабораторной по документированию API).
24. Документация **RQ (Redis Queue)** / **Arq** — асинхронные очереди задач для воркер-пула (§3).

## 7. Версионирование и базы данных

25. ★ Чакон С., Штрауб Б. «Pro Git» (глава «Внутреннее устройство Git»). — Модель объектов Git (blob/commit/tree) — прямая основа таблиц `commits`/`blobs` с дедупликацией (§6).
26. Документация PostgreSQL по типу `JSONB` — хранение метаданных версий и истории AI-запросов без потери реляционной целостности.

## 8. Предметно-ориентированное проектирование (DDD)

27. Эванс Э. «Предметно-ориентированное проектирование» (Domain-Driven Design). — Bounded Contexts — обоснование границ между доменами Пользователей/Версионирования/Рендеринга.
28. Вернон В. «Реализация методов предметно-ориентированного проектирования» (Implementing DDD). — Практические паттерны поверх теории Эванса.

## 9. Frontend и конструирование IDE-интерфейсов

29. Тидвелл Дж. «Designing Interfaces». — Паттерны сложных рабочих пространств (панели, сплиты) — обоснование layout split-view редактор/канвас.
30. ★ Круг С. «Не заставляйте меня думать» (Don't Make Me Think). — Юзабилити панелей и навигации IDE.
31. Ватан А., Шогер С. «Refactoring UI». — Практика дизайн-системы (цвет, типографика, плотность) — применено к палитре и шрифтовой паре Inter/Source Code Pro.
32. Официальная документация **React** (react.dev) — компонентный подход, Virtual DOM.
33. Документация **Monaco Editor** — встраивание редактора кода, кастомный язык подсветки синтаксиса для DSL.
34. Документация **Vite** — сборка и HMR.
35. Документация **Zustand** / **Redux Toolkit** — глобальное состояние (активная тема, стек Undo/Redo).
36. Документация **TanStack Query (React Query)** — синхронизация состояния сервера, кэш ответов API.
37. Спецификация **Language Server Protocol (LSP)** — следующий шаг после базовой подсветки: вынесение диагностики DSL в отдельный сервис.

## 10. Веб-доступность и стандарты разметки

38. Стандарт **WCAG** и ARIA-атрибуты (MDN) — роли доступности (`role="dialog"` для AI-модалки и т.п.), требование лабораторной №3.
39. Документация **Schema.org** — микроразметка `Organization`/`Person` (вариант 13 методички).

## 11. Системный дизайн и паттерны проектирования

41. ★ Гамма Э., Хелм Р., Джонсон Р., Влиссидес Дж. «Приёмы объектно-ориентированного проектирования» (Design Patterns, «Банда четырёх»). — Strategy (провайдеры хранения), Visitor (обход AST), Factory (создание узлов по типу нотации).

### Как использовать этот список в РПЗ

Раздел «Список использованных источников» требует 15–20 позиций по ГОСТу/СТП. Отмеченные ★ пункты (16 штук) — рекомендованный минимальный набор: они покрывают все главы РПЗ (анализ и проектирование, реализация, распределённые системы, UML, тестирование, безопасность) и не дублируют друг друга по теме. Полный список выше можно использовать как рабочую базу и для более развёрнутых упоминаний по тексту глав («см. например, Клеппман [8]»).
