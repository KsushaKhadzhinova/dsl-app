# Задачи, которые может выполнить только сама Ксения

**Статус:** актуально
**Зачем этот документ:** здесь собрано всё, что ИИ-ассистент технически не может сделать сам — либо потому что это требует её личных учётных данных/аккаунтов, либо потому что классификатор безопасности Claude Code блокирует конкретную git-команду как потенциально разрушительную. Ничего из этого не забыто случайно — каждый пункт заблокирован по конкретной причине, указанной рядом.

## 1. Git — одна конкретная команда (заблокирована классификатором)

```bash
git branch -f feature/notation-bpmn-and-collab a2d8c2d
```

Убирает случайно попавший на эту ветку чужой коммит (`45c8032`, относится к фронтенду, не к бэкенду). Проверено: коммит безопасно дублирован на правильной ветке `feature/real-ide-app`, ничего не потеряется. Claude не может выполнить `git branch -f` сам — команда отклоняется как потенциально разрушительная (перезапись ссылки ветки), даже когда безопасна.

## 2. Решение о мерже веток в `main`

Ветки `feature/notation-bpmn-and-collab` (бэкенд) и `feature/real-ide-app` (фронтенд + вся документация) готовы, но не смёржены в `main` — ждут твоего явного "да, мержи". Пока не смёржено — учти, что `docs/`, `AI_CONTEXT.md`, реальный IDE и т.д. физически существуют только на `feature/real-ide-app`.

## 3. Расхождение `main` и `origin/main` на GitHub

Локальный `main` и `origin/main` (GitHub) не имеют общего предка (см. `AI_CONTEXT.md`, §4) — почти наверняка из-за твоего `git filter-branch`. Ничего не потеряно, но обычный `git push`/merge поведёт себя не как обычно. Нужно решить вместе (например через rebase), не как рутинную операцию — не проси ИИ-ассистента "просто запушить `main`" без предварительного разбора этого момента.

## 4. GitHub / Google OAuth-приложения (если решишь делать FR-AUTH-04, FR-STORE-02/03)

ИИ не может создать OAuth-приложение за тебя — регистрация делается вручную под твоим аккаунтом:

- **GitHub**: [github.com/settings/developers](https://github.com/settings/developers) → New OAuth App → указать Homepage URL и Authorization callback URL (например `http://localhost:5173/auth/callback/github` для локальной разработки) → скопировать `Client ID` и сгенерировать `Client Secret`.
- **Google**: [console.cloud.google.com](https://console.cloud.google.com) → создать проект → APIs & Services → Credentials → Create OAuth client ID → тип "Web application" → указать те же redirect URI → получить `Client ID` и `Client Secret`.

Когда получишь оба набора ключей — впиши их в `backend/.env` (`GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET`, `GOOGLE_OAUTH_CLIENT_ID`/`GOOGLE_OAUTH_CLIENT_SECRET`) и скажи мне — реализую реальный flow поверх готовых ключей.

## 6. Реальный `DATABASE_URL` для основного FastAPI-бэкенда (Neon)

У тебя уже есть Neon-проект "diagramcode", подключённый к лабе 2 части 2 (Node.js/Sequelize). Для настоящего продукта (FastAPI-бэкенд на ветке `feature/notation-bpmn-and-collab`) нужен **отдельный** `DATABASE_URL` в `backend/.env` — можно either создать ещё один Neon-проект, либо (проще) отдельную базу внутри того же проекта, чтобы таблицы Node-лабы и настоящего продукта не пересекались. Точная инструкция — `docs/setup/00-developer-setup.md`, §7.

## 8. GlitchTip DSN (опционально, для реального трекинга ошибок)

Фоновый агент подключает `sentry-sdk`-совместимый трекинг ошибок (GlitchTip), но без реального DSN он просто отключён (не ломает работу приложения). Если хочешь реальный трекинг — заведи бесплатный аккаунт на [glitchtip.com](https://glitchtip.com) (или разверни self-hosted), создай проект, скопируй DSN в `backend/.env` как `GLITCHTIP_DSN`.
