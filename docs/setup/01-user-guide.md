# Руководство пользователя

**Статус:** актуально (описывает то, что реально работает на текущий момент — см. `../requirements/04-traceability-matrix.md` за полным статусом; здесь только то, что готово)

## Что такое DiagramCode

Веб-сервис, где диаграмма описывается текстовым кодом на собственном DSL (а не мышью в графическом редакторе), а рядом сразу видно её визуальный рендер — «диаграмма как код», по аналогии с Terraform для инфраструктуры.

## 1. Регистрация и вход

Открой `http://localhost:5173/register`, укажи email, имя пользователя и пароль. После регистрации — вход на `/login` по email и паролю. Без входа приложение не пускает дальше экрана логина.

## 2. Экран IDE

После входа открывается редактор со следующими зонами:

- **Титлбар** (сверху) — логотип, выбор нотации, путь к файлу, кнопки **Run** / **Save** / **Export** / **Import**, переключатель темы, аватар/выход.
- **Боковая панель активности** (слева, узкая) — иконки разделов; на сегодня рабочий раздел — «Шаблоны/Файлы».
- **Сайдбар** — список твоих диаграмм и доступных нотаций.
- **Редактор кода** (Monaco, по центру) — с подсветкой синтаксиса DSL.
- **Канвас** (справа) — визуальный рендер текущего кода.
- **Нижняя панель** — вкладки **Terminal** (лог последнего действия) и **Problems** (ошибки/предупреждения валидации).
- **Статус-бар** (снизу) — активная нотация, позиция курсора, статус синхронизации, переключатель языка (RU/EN).

## 3. Синтаксис DSL

Диаграмма — это блок `diagram <нотация> "<Название>" { ... }`, внутри — узлы и связи:

```
diagram erd.crows_foot.logical "Заказы" {
  entity customer "Клиент" pk=id
  entity order "Заказ" pk=id
  customer -> order
}
```

- Узел: `<тип> <идентификатор> "<подпись>" [атрибут=значение ...]` — например `entity customer "Клиент" pk=id`.
- Связь: `a -> b`, можно цепочкой `a -> b -> c`.
- Связь с подписью условия: `a -["условие"]-> b`.
- Комментарии: `// текст` — игнорируются при разборе.

## 4. Доступные нотации на сегодня

Сейчас зарегистрированы и реально работают:
- **`erd.crows_foot.logical`** — ER-диаграммы, стиль Crow's Foot. Сущность без `pk` — не ошибка, а предупреждение (диаграмма всё равно отрисуется).
- **`bpmn.process`** — базовый BPMN: стартовые/конечные события, задачи, последовательные потоки. Диаграмма без стартового/конечного события или со связью на несуществующий узел — ошибка валидации, рендер не выполняется.

Остальные нотации (UML, IDEF0/1X/3, DFD, сети Петри, другие виды BPMN) показаны в интерфейсе для полноты, но пока недоступны для выбора — они запланированы на следующие волны разработки (см. `../requirements/00-overview.md`, §1).

## 5. Run, Save, Export, Import

- **Run** — разобрать и отрендерить текущий код. Ошибки синтаксиса и валидации показываются во вкладке **Problems**; сам рендер отображается на канвасе, только если нет ошибок уровня error (предупреждения не блокируют).
- **Save** — сохранить текущий код как новую версию диаграммы. Повторное сохранение без изменений не создаёт лишнюю копию содержимого (внутренняя дедупликация).
- **Export** — скачать текущую диаграмму на устройство.
- **Import** — загрузить существующий `.dsl`-файл в редактор.

## 6. Тема и язык

Переключатель темы в титлбаре — тёмная/светлая (это два независимых набора цветов, а не инверсия одного). Переключатель языка в статус-баре — русский/английский, применяется сразу, без перезагрузки страницы.

## 7. Совместная работа (в разработке)

Добавление соавторов и одновременное редактирование одной диаграммы несколькими пользователями — в разработке; на сегодня безопасно считать диаграмму рабочим пространством одного пользователя.

## 8. Если что-то не работает

- Экран логина не пускает дальше — проверь, что backend реально запущен (см. `00-developer-setup.md`) и доступен по адресу, на который настроен фронтенд.
- AI-функции (кнопка AI, распознавание изображений) — ещё не подключены к интерфейсу на этом этапе, даже если backend их уже поддерживает.
- История версий и совместное редактирование как отдельные экраны — тоже ещё не подключены к интерфейсу.
