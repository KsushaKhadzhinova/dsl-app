# Software Requirements Specification (SRS) — DiagramCode

**Статус:** актуально
**Формат:** соответствует структуре IEEE 830 / ГОСТ 19.201, адаптирован под структуру проекта. Детальное содержание каждого раздела вынесено в отдельные файлы этой папки — здесь сводная спецификация со ссылками, чтобы не дублировать содержимое в двух местах.

## 1. Введение

### 1.1 Назначение
Сервис DiagramCode — веб-приложение для описания и рендеринга диаграмм через собственный текстовый DSL, с версионированием, AI-генерацией и совместным редактированием.

### 1.2 Область действия
См. `01_requirements/BRD_business_requirements_document.md`, §4.

### 1.3 Определения и сокращения
См. глоссарий в `01_requirements/00-overview.md`, §4 (DSL, нотация, коммит/блоб, волна, режим AI).

### 1.4 Ссылки
- `01_requirements/business_requirements.md` — бизнес-требования
- `01_requirements/user_requirements.md` — пользовательские требования
- `01_requirements/01-functional-requirements.md` — функциональные требования (FR)

## 2. Общее описание

### 2.1 Контекст продукта
Модульный монолит (FastAPI + PostgreSQL + Redis + воркер-пул) с реестром плагинов нотаций и React/Monaco фронтендом. Полное обоснование — `02_architecture_diagrams/00-system-architecture.md`.

### 2.2 Функции продукта (сводно)
1. DSL-редактор с подсветкой синтаксиса и валидацией (FR-DSL-*, FR-NOT-*)
2. Рендеринг диаграмм в SVG (FR-REN-*)
3. Git-подобное версионирование (FR-VER-*)
4. AI-ассистент — генерация по тексту/изображению (FR-AI-*)
5. Хранение и экспорт в несколько форматов (FR-STORE-*)
6. Аутентификация и авторизация, включая соавторство (FR-AUTH-*)

### 2.3 Классы и характеристики пользователей
См. `01_requirements/00-overview.md`, §3 (акторы).

### 2.4 Ограничения
См. `01_requirements/BRD_business_requirements_document.md`, §6.

### 2.5 Допущения и зависимости
Бесплатная облачная инфраструктура (Neon/Render/Netlify), см. архитектура §7.

## 3. Специфические требования

### 3.1 Функциональные требования
Полный перечень с волнами реализации — `01_requirements/01-functional-requirements.md` (8 групп, ~90 требований).

### 3.2 Нефункциональные требования
Полный перечень — `01_requirements/02-nonfunctional-requirements.md` (9 групп: производительность, безопасность, надёжность, наблюдаемость, доступность, совместимость, поддерживаемость, инфраструктура, PWA).

### 3.3 Требования к интерфейсам
- Внешние API: REST (`/api/v1/*`), WebSocket (уведомления в реальном времени).
- Пользовательский интерфейс: см. мокапы в `03_mockups_wireframes/` — это не иллюстрации, а нормативная спецификация поведения UI (список статусов, состав меню и т.д. нигде больше текстом не зафиксированы).

### 3.4 Модель данных
См. `02_architecture_diagrams/02-diagrams.md` и `02_architecture_diagrams/diagrams/data-model.png`.
